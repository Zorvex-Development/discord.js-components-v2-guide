# Contributing to the Zorvex Components V2 Handbook

This handbook is maintained by Zorvex Development. Contributions should improve correctness, clarity and practical value rather than simply add length.

## Before opening a change

- Check the current Discord and discord.js references for API behaviour that can change.
- Use original explanations and examples. Do not transplant another author's prose, branding, invite links or demo data.
- Prefer a runnable CommonJS example unless the page explicitly explains another module system.
- Keep permissions, validation and failure handling visible in interaction examples.
- Avoid implying that this document is an official Discord resource.

## Review checklist

1. Is every symbol imported in a complete code sample?
2. Is the code compatible with the stated version range?
3. Are V2 flag and legacy payload restrictions explained where relevant?
4. Are stale interactions, access checks and acknowledgement timing addressed when relevant?
5. Does the page link to official documentation for rules that can change?
